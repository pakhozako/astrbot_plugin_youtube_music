# 使用

[文档目录](index.md) / 使用

## QQ 指令

下面使用 AstrBot 默认的 `/` 前缀；自定义唤醒前缀时替换为宿主设置的前缀。
搜索、收藏和历史属于当前用户与当前会话；同一群的点歌队列由成员共享。

### 搜索与点歌

| 指令 | 操作 |
| --- | --- |
| `/点歌` | 查看帮助 |
| `/点歌 帮助` | 查看帮助并登记当前会话 |
| `/点歌 <关键词>` | 搜索歌曲或艺人 |
| `/点歌 歌手 <名字>` | 按歌手关键词搜索 |
| `/点歌 <编号> [结果码]` | 将本人的搜索候选加入群队列 |
| `/点歌 <视频链接>` | 通过 YouTube 视频链接点歌 |
| `/点歌 下一页` / `/点歌 上一页` | 翻阅本人的搜索列表 |
| `/点歌 翻页 <页码>` | 查看指定页 |
| `/点歌 重搜 [关键词]` | 使用新关键词或上次关键词重新搜索 |
| `/点歌 重新搜索 [关键词]` | 与重搜相同 |
| `/点歌 取消搜索` | 取消本人进行中的搜索，不改变队列 |
| `/点歌 详情 <编号> [结果码]` | 按需查看歌曲信息与封面 |
| `/点歌 队列` | 查看当前队列 |
| `/点歌 状态` | 查看当前队列 |

搜索结果包含请求者、标题、歌手、时长及能从元数据识别的版本线索。可同时输入歌名、歌手和版本，
例如 `/点歌 Adele Hello live`。官方音频、MV、Live、翻唱和 Remix 标签是标题或频道线索，不是官方身份认证。
正在直播、预约、时长未知或超限的候选会排除；已结束的演出存档仍可点播。

每次搜索仍只获取原有的三倍候选池，筛选、排序和保守去重后按配置分页；翻页不再访问 YouTube。
编号在整个候选池中连续，第二页不会重新从 1 开始。搜索数量、候选有效期与自动撤回参数见[配置参考](CONFIGURATION.md)。

常用点歌仍只需 `/点歌 <关键词>` 后发送 `/点歌 1`。裸编号始终指向本人当前会话的最新列表，
无法识别用户正在看哪一条旧消息。列表中的 8 位结果码可消除这种歧义：
若结果码为 `a1b2c3d4`，发送 `/点歌 1 a1b2c3d4`；旧搜索或他人的结果码会拒绝，
翻页仍沿用同一结果码。详情和收藏也支持结果码。重新搜索不会替换其他成员的列表。

支持 YouTube watch、youtu.be、Shorts、live、embed、music.youtube.com 和 youtube-nocookie.com 的单视频链接，
以及支持域名的无协议分享地址。链接中的播放列表和时间参数不会扩大点播范围；纯播放列表不支持。
详情只发一条消息，封面限时 4 秒、限量 1 MiB 获取；获取失败仍返回文字，不额外通知。

### 收藏与历史

| 指令 | 操作 |
| --- | --- |
| `/点歌 收藏 <编号> [结果码]` | 收藏本人的搜索候选 |
| `/点歌 收藏列表` | 查看收藏 |
| `/点歌 播放收藏 <编号>` | 将收藏歌曲加入队列 |
| `/点歌 取消收藏 <编号>` | 移除收藏 |
| `/点歌 最近` | 查看最近 10 条语音历史 |
| `/点歌 重播` | 将本人最近提交的歌曲加入队列 |
| `/点歌 重播 <历史编号>` | 重播最近一次展示的历史列表中的歌曲 |
| `/点歌 随机` | 从本人的收藏与历史中随机点一首 |
| `/点歌 清除历史` | 清除历史 |

QQ 音乐库对应当前用户和聊天会话；控制台音乐库对应 AstrBot 提供的登录身份。
历史编号绑定最近一次 `/点歌 最近` 展示的快照，后续语音提交不会移动该快照的编号；过期后需再次查看。
清除历史后不能使用旧编号重播。收藏列表编号与搜索编号相互独立。

随机点歌排除当前歌曲、已排队歌曲及不符合当前时长和音频预算的歌曲，不读取其他成员的记录。
歌手搜索复用已有关键词搜索。当前未提供相似歌曲推荐，避免引入没有可靠推荐来源的额外交互。

### 队列操作

| 指令 | 操作 |
| --- | --- |
| `/点歌 取消` | 取消自己加入的待播歌曲 |
| `/点歌 移除 <编号>` | 移除指定待播歌曲 |
| `/点歌 继续` | 继续处理队列 |
| `/点歌 暂停` | 暂停队列处理 |
| `/点歌 下一首` | 跳过当前处理项并继续 |
| `/点歌 清空队列` | 清空待播列表 |

同一群聊共用 FIFO 队列。各项操作的授权见[安全指南](https://github.com/pakhozako/astrbot_plugin_youtube_music/blob/main/SECURITY.md)。

入队只回复一条确认，包含歌曲信息、前方曲目数或暂停状态。同一视频在当前处理、语音等待和待播队列中不重复加入；
不同群互不影响。排队提示中的播放等待按当前剩余等待与前方音频时长估算，不包含下载、转码和资源等待开销。

下载、校验、转换和发送阶段通过 `/点歌 状态` 或控制台查看，不自动逐阶段发送群消息。
自动撤回启用时，选歌、翻页或重搜触发旧搜索消息清理；只有身份和内容核对一致时才申请撤回，平台拒绝时保留消息。
OneBot 没有通用的消息编辑接口，因此不假定能直接修改已发出的群消息。

普通成员只能取消或移除自己的待播项；取消本人进行中的下载也不会删掉其他人的歌曲。
已提交的语音不会因取消而撤回，自己的取消操作保留当前语音等待。管理员的下一首、暂停和清空可以结束处理或等待，
但无法停止客户端已经开始播放的语音。

已知时长和预计 WAV 容量在入队及下载前预检，转换后仍以实际音频校验为准。
只有明确的暂时网络错误会重试一次，复用原阶段超时预算；发送不自动重试。
语音提交超时的结果未知，不再追加链接或另一条语音，需先核对群消息再手动处理。

## 控制台

从 AstrBot 插件详情打开 `console`，在顶部选择目标会话。使用过点歌指令的 QQ 会话会显示在列表中。

| 页面 | 常用操作 |
| --- | --- |
| 搜索 | 输入关键词，查看封面和歌曲信息，收藏或加入目标队列 |
| 队列 | 查看当前阶段与待播总时长，继续、暂停、下一首、上下移动、移除、清空队列和移除空会话 |
| 音乐库 | 分页浏览收藏与历史，跨页选择、筛选、排序、整批入队、从历史收藏、移除收藏和清除历史 |
| 维护 | 查看运行状态，管理依赖更新和音频缓存；详细步骤见[依赖指南](DEPENDENCIES.md) |

控制台同步 AstrBot 的主题与语言。执行清空、缓存清理或依赖更新时，核对确认窗口中的操作目标。

### 批量点歌

音乐库每页显示 20 首，可逐首选择或选择本页，跨页最多选择 20 首。筛选和排序会回到第一页，
但不会清除已选曲目；收藏与历史分别保留各自的选择。刷新时，来源中已删除的曲目会从选择中移除。

点击 **批量入队** 后核对目标会话与完整曲目列表。入队顺序遵循当前排序，包含其他页及暂时被筛选隐藏的已选曲目。
确认窗口的队列容量来自最近状态，仅作预览；服务端以实际提交时的状态为准。

已在目标队列或当前处理/语音等待中的歌曲会跳过，其余曲目整批写入。容量不足、曲目已不在当前身份的来源列表中、
元数据或时长不合法时，整批不加入；错误后保留选择。成功提示显示实际加入和跳过数量。
提交后不要因网络响应不确定立即重试，先刷新目标队列核对结果。

### 历史与恢复

历史的次数与时间记录的是语音提交，不证明客户端已播放完毕。可以按最近提交或最多提交排序，
直接收藏一首历史歌曲；已收藏的歌曲不会重复写入，也不改变原收藏信息。

待播总时长仅统计持久队列中的歌曲，不计下载、转换、发送和排队开销，也不计已提交后等待的当前项，
因此不是预计开始时间。时长未知的曲目会单独标注，重新入队仍须通过时长限制。

错误或暂停队列点击 **继续** 时会显示确认窗口，包括重启后仍暂停但已无运行时错误信息的队列。
语音提交超时或状态保存失败可能已向 QQ 提交消息，继续可能再次发送当前项；
先核对目标会话，再决定继续、移除该项或跳过。QQ 指令和 AI Tool 的手动继续同样需要核对结果。

## AI Tool

在 AstrBot 的人格工具设置中启用 `youtube_music`，并使用支持工具调用的模型。

可以向机器人说“搜索 piano”，查看候选后回复“播放第 1 首”。Tool 使用当前聊天会话执行操作。

以下是工具参数示例：

```json
{"action": "search", "query": "piano"}
```

```json
{"action": "enqueue", "index": 1}
```

| action | 参数 | 操作 |
| --- | --- | --- |
| `search` | `query` | 搜索歌曲 |
| `enqueue` | `index` 或包含视频链接的 `query` | 将已选歌曲加入队列 |
| `queue_status` | 无 | 查看队列 |
| `resume` | 无 | 继续队列 |
| `pause` | 无 | 暂停队列 |
| `next` | 无 | 下一首 |
| `cancel` | 无 | 取消自己的待播歌曲 |
